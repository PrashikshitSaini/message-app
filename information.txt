User Commands


Login

- packet: (int) opcode=03, (String) UID, (String) ASCII password, (byte array, 256 bit) Session token

- error opcodes:

• 04 – Invalid Credentials (includes random number incorrect)

- UID: User ID, uniquely chosen at account creation, different than display name(s).


Account Creation

- packet: (int) opcode=01, (String) username, (String) ASCII password

- error opcodes:

• 01 – Taken/Restricted Username

• 02 – Invalid Password Values

- The username chosen here (if not taken) becomes the User ID (UID) used for most backend operations.

• This is different than display name, which defaults to UID or can be randomly generated at the start

• Each team can choose what they want, just keep display name and UID separate


“Poke” User in Chat

- packet: (int) opcode=02, (byte array, 256 bit) Session token, (String) Chat ID, (String) username to poke

- error opcodes:

• 22 – Chat ID Invalid/Does Not Exist

• 03 – Username does not exist

- Depending on each team’s UI design, the user may or not be able to poke by UID, display name (both as arguments in in-app scripting like @ in discord), or via UI (such as a generic drop-down for each user).

• Most secure practice is to use UID on backend and disallow UID being shown to user doing the poking.


** This is needed so that clients know what they can and cannot do.

Query a User’s Own Permissions in Chat

- packet: (int) opcode=04, (byte array, 256 bit) Session token, (String) Chat ID

- Response packet: (int) opcode=00, (byte array, 256 bit) Session token, (int) permissions

- Permissions 0=no permissions, 1=write permissions, 2=query users in chat [Note: if all permissions are granted, 3 would be sent, as the permissions are added.]

- error opcodes:

• 22 – Chat ID Invalid/Does Not Exist



Block User

- packet: (int) opcode=11, (byte array, 256 bit) Session token, (String) username to block

- error opcodes:

• 03 – Username does not exist

• 11 – User is blocked (No reason to block a second time)

- Backend could use UID, but user should be able to block by UID, display name, or a user interface dialog (the last two protect blocked user security by not giving/requiring UID)


Unblock User

- packet: (int) opcode=12, (byte array, 256 bit) Session token, (String) username to unblock

- error opcodes:

• 03 – Username does not exist

• 12 – Unable to Unblock

- Backend could use UID, but user should be able to unblock by UID, display name, or a UI dialog (the last two protect blocked user security by not giving/requiring UID)


List/Query Blocked Users

- packet: (int) opcode=13, (byte array, 256 bit) Session token

- Response packet: (int) opcode=00, (byte array, 256 bit) Session token, (string) blocked UIDs separated by BEL

- error opcodes:

• 13 – Could not retrieve user(s)

• 12 – Unable to Unblock

- This list will show all blocked users

• Features such as querying the list for a specific display name/UID may require another packet/different opcode with the name/UID of the user being queried

• For security, it may be best to only show display names to users, but teams are free to do as they choose regarding this

- This is an OPTIONAL feature


** This is needed for security so that owners and some users know who is in their chat.

List/Query Users in Chat

- packet: (int) opcode=14, (byte array, 256 bit) Session token, (String) chat ID

- Response packet: (int) opcode=00, (byte array, 256 bit) Session token, (string) UIDs separated by BEL

- error opcodes:

• 22 – Chat ID Invalid/Does Not Exist

- This list will show all users in a chat

• Features such as querying the list for a specific display name/UID may require another packet/different opcode with the name/UID of the user being queried

• For security, it may be best to only show display names to users, but teams are free to do as they choose regarding this



Chat Commands


Create Chat

- packet: (int) opcode=21, (byte array, 256 bit) Session token, (String) Chat Name

- response packet: (int) opcode=00, (String) chatId(determined by the server)

- error opcodes:

• 21 – Disallowed/Duplicate Chat ID

- Current specifications label the chat name as its unique ID

• May need to change this to the name plus UID or other info to solve the below issues

- Duplicate prevention is complicated and as yet undefined:

• Is it no duplicates created by one user (a user could join one chat and create their own chat with the exact same name/ID if this is the case, which may affect server)

• If duplicates of any name/Server ID (SID) are disallowed, names of similar server may allow attack surface analysis (i.e. “the quacks” is disallowed even though “the quicks” and “tha quacks” are available, meaning “the quacks” exists as a chat somewhere). It also limits the number of possible chats the userbase can create.


Add User to Chat

- packet: (int) opcode=22, (byte array, 256 bit) Session token, (String) Chat ID, (String) username to add

- error opcodes:

• 03 – Username does not exist

• 11 – User is blocked

• 22 – Chat ID Invalid/Does Not Exist

- This invites a specific individual to the chat (different from sending a generic chat invite, see below)

• This is serviced/used by the chat creator/admin/server

• This could be used as a means of access control by withholding any permissions/privileges in the chat unless explicitly approved through this control (for users joining via link).

• Sending this to a user who has not attempted to join via link may generate a link?


Remove User from Chat

- packet: (int) opcode=23, (byte array, 256 bit) Session token, (String) Chat ID, (String) username to remove

- error opcodes:

• 03 – Username does not exist

• 22 – Chat ID Invalid/Does Not Exist

- This does not prevent removed users from rejoining or reusing generic invite links (i.e. this is not a ban, which may require different functionality)




Delete Chat

- packet: (int) opcode=24, (byte array, 256 bit) Session token, (String) Chat ID

- error opcodes:

• 22 – Chat ID Invalid/Does Not Exist

- Cannot recover deleted chats

• How/what is deleted on both client/server with this command is not yet defined, and will be up to teams to determine where this packet gets sent and what sends it


Leave Chat

- packet: (int) opcode=32, (byte array, 256 bit) Session token, (String) Chat ID

- error opcodes:

• 22 – Chat ID Invalid/Does Not Exist


Change Chat’s Display Name in Chat

- packet: (int) opcode=33, (byte array, 256 bit) Session token, (String) Chat ID, (String) chat’s display name

- error opcodes:

• 22 – Chat ID Invalid/Does Not Exist

• 06 – Invalid/Restricted Display Name

- Response: (String) message id

- error opcodes:

• 22 – Chat ID Invalid/Does Not Exist

• 41 – Invalid message content

• 42 – invalid message type/format

- After sending, may need to refresh in order to


Edit Message in Chat

- packet: (int) opcode=42, (byte array, 256 bit) Session token, (String) Chat ID, (String) message id, (String) updated message, (int) updated message type [for future use set to 00 for default]

- error opcodes:

• 22 – Chat ID Invalid/Does Not Exist

• 41 – Invalid message content

• 42 – invalid message type/format

• 43 – invalid message ID

- packet: (int) opcode=43, (byte array, 256 bit) Session token, (String) Chat ID, (String) message id

- error opcodes:

• 22 – Chat ID Invalid/Does Not Exist

• 43 – invalid message id


Pin Message in Chat

- error opcodes:

• 22 – Chat ID Invalid/Does Not Exist

• 43 – invalid message id


Unpin Message in Chat

- packet: (int) opcode=45, (byte array, 256 bit) Session token, (String) Chat ID, (String) message id

- error opcodes:

• 22 – Chat ID Invalid/Does Not Exist

Role Commands


Request Chat(s)

- packet: (int) opcode=26, (byte array, 256 bit) Session token

- response: (String) Chat IDs separated by BEL [07 or \a], (String) Chat names separate by BEL

- For example, response “<Chat ID>BEL<Chat name>BEL<Chat ID>...”

- -error opcodes:

• 22 – Chat ID Invalid/Does Not Exist (If selecting multiple use a different opcode?)


Request Messages in Chat

- packet: (int) opcode=46, (byte array, 256 bit) Session token, (String) Chat ID, (int) starting message index [earliest requested message in chat, 0 = first message sent in chat], (int) ending message index [set to -1 for all]

- response: (String) usernames separated by BEL [07 or \a], (String) messages separated by BEL [07 of \a], (String of an int) message type separated by BEL [07 or \a], (String of an int) time given in ms since the epoch in UTC separated by BEL [07 or \a], (String) message IDs separated by BEL [\a]

- error opcodes:

• 22 – Chat ID Invalid/Does Not Exist

• 44 – invalid starting message index

• 45 – invalid ending message index


** This is needed so that clients are not overwhelmed by messages when they first log in.

Request Latest Message Index in Chat

- packet: (int) opcode=47, (byte array, 256 bit) Session token, (String) Chat ID

- response: (int) latest message index

- error opcodes:

• 22 – Chat ID Invalid/Does Not Exist


** This is needed so that clients can find pinned chats.

Request Pinned Message Index in Chat

- packet: (int) opcode=48, (byte array, 256 bit) Session token, (String) Chat ID

- response: (String as int) message ID of pinned messages separated by BEL

- error opcodes:

• 22 – Chat ID Invalid/Does Not Exist


Create Role in Chat

- packet: (int) opcode=61, (byte array, 256 bit) Session token, (String) Chat ID, (String) role name, (int) permissions

- Permissions: 0=none, 1=write, 2=view users (Permissions are added together)

- error opcodes:

• 22 – Chat ID Invalid/Does Not Exist

• 61 – Role name invalid

• 63 – Invalid permissions


Add Role to User in Chat

- error opcodes:

• 03 – Username does not exist

• 62 – Role (name) does not Exist

- error opcodes:

General Info

- All successful operations shall send the success opcode: 00

- unknown “opcode” opcode: 100

- unknown error opcode: 101

- All packets shall send the token immediately after the opcode unless specifically specified otherwise


Additional:

- Send authentication token as a byte array, not 4 integers

- Integers are int64

- Strings are utf8 encoded

- Add:

- Authentication token at the front of every package

- Error codes for lack of permissions/invalid authentication token

- Change credentials error codes only send client a general "invalid credentials" message rather than a separate one for username and password: error code

- More specifics in role creation permissions

- Delete/edit message permissions

- Server will send its own 256-bit authentication token for verification

- Add Diffie-Helman

- Poke: sends a notification to a specific user. Like typing "@name" on Discord, but without the added message

- Store message times in ms, only display to second/minute, compensate for UTC

- Keep chat IDs in separate packets from message IDs/indexes

- For message type format shall be an integer of the form XX. The first digit shall correspond to whether a message is pinned. 0X shall be unpinned and 1X shall be pinned. The second digit shall correspond to whether a message has been edited or deleted or is a poke. X0 shall be normal message. X1 shall be edited message. X2 shall be deleted message (the message should have no contents). X3 shall be a poke message with the contents being the UID of the person poked.

- Add message change type command (pings, pins?)

• Options and type are 2 separate fields in each message
